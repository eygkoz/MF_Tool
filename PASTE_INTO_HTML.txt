====================================================================
1) Add inside <head>, right after your existing
   <link rel="apple-touch-icon" ...> line (around line 13)
====================================================================

<link rel="manifest" href="/MF_Tool/manifest.json">
<link rel="apple-touch-icon" sizes="180x180" href="/MF_Tool/icons/icon-180.png">

Your existing inline-SVG apple-touch-icon on line 13 can stay as a
fallback, or you can delete it now that a real PNG is provided above --
either is fine.


====================================================================
2) Add just before the closing </body> tag
====================================================================

<script>
if ("serviceWorker" in navigator) {
  window.addEventListener("load", () => {
    navigator.serviceWorker.register("/MF_Tool/sw.js").catch((err) => {
      console.warn("Service worker registration failed:", err);
    });
  });
}
</script>

4) One thing to double check
====================================================================

I fetched https://eygkoz.github.io/MF_Tool/ and it correctly loaded
your tool at that exact URL (no filename in the address), so Pages is
already serving your file as the directory index -- meaning it's
either named index.html in the repo, or GitHub Pages is otherwise
resolving it that way. Either way, start_url "/MF_Tool/" in
manifest.json (as written) is correct and doesn't need to change.

After committing all the files above, hard-refresh the live site once
(or open it in an incognito tab) before re-running it through
PWABuilder -- browsers/PWABuilder can cache a "no manifest" result
from before you added it.
